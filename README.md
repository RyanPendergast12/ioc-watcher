# IOC Watcher

Daily threat-intel collector with a **human-in-the-loop Discord approval** step.
New IOCs and research are matched to pages in an Obsidian threat-intel vault, proposed in Discord, and only written to the vault after you hit **Approve**.

```
 SOURCES (daily)                    DETECT (GitHub Action)                    DISCORD #ioc-review
 abuse.ch · blocklists · KEV   ──▶  fetch → extract → classify ──▶ pending/ ──▶  🚨 card  [✅ Approve] [❌ Deny] [📝 Edit]
 30 research blogs · IOC repos      (mapping.yml → vault page)                          │ click
                                                                                         ▼
 OBSIDIAN VAULT (laptop)  ◀── vault_sync.py ◀── approved/ ◀── APPLY (GitHub Action) ◀── Cloudflare Worker
 page.md "## IOC Watcher"      every 15 min      archive/denied/   repository_dispatch     (verifies Discord signature
                                                                                          + approver allowlist)
```

## What goes where

| What | Routed to (vault-relative) |
|---|---|
| IOCs attributed to a family/actor you have a page for (ThreatFox, MalwareBazaar, Feodo, SSLBL, URLhaus tags, TweetFeed tags, OTX pulses) | that page, e.g. `Threat Intel/Malware Families/Infostealers/Vidar.md` |
| Research blog posts / IOC-repo files that mention one of your pages | that page → `### Recent Reporting` (+ IOCs pulled from the post, assigned to the best-matching page) |
| Every new research post (DFIR Report, ReliaQuest, Unit 42, Huntress, Talos, …) | `Threat Intel/Intel Feed/YYYY-MM-DD.md` (daily digest) |
| IPs seen in ≥2 independent reputation lists the same day; new Spamhaus DROP ranges; VXVault | `Threat Intel/Raw Threat Intel/BAD IPS.md` |
| Phishing / malware-download / C2-panel domains (OpenPhish, PhishTank, VXVault, CyberCrime Tracker) | `Threat Intel/Raw Threat Intel/BAD DOMAINS.md` |
| Unattributed hashes / SSL cert fingerprints | `Threat Intel/Raw Threat Intel/BAD HASHES.md` |
| New CISA KEV entries | `Vulnerability Management/CISA KEV.md` |

Everything is appended under a single `## IOC Watcher` section at the bottom of the page (sub-headings per type), de-duplicated against what the page already contains. Existing content is never modified.

Volume is capped so a card stays reviewable on a phone (`config/settings.yml`): 75 items per page per day, 60 per raw bucket (max 20 from any one feed), 150 per article. IOCs are never re-proposed within 180 days.

## Repo layout

```
config/sources.yml      every source (enable/disable, URLs) — dead/unsupported feeds documented at the top
config/settings.yml     caps, consensus threshold, look-back windows
config/aliases.yml      hand-curated vendor aliases → vault page titles (APT29 = Midnight Blizzard, …)
config/mapping.yml      GENERATED by tools/build_mapping.py from vault file names
watcher/                detect.py · post.py · apply.py · sources.py · classify.py · iocs.py · discord.py
worker/                 Cloudflare Worker = Discord interactions endpoint
sync/vault_sync.py      laptop-side writer (Task Scheduler)
pending/ approved/ archive/denied/   proposal store
state/state.json        seen-IOC tracker + per-source cursors;  state/last_run.md = last run's source health
```

## Setup

### 1. API keys (GitHub → repo Settings → Secrets and variables → Actions)

| Secret | Needed for | Where |
|---|---|---|
| `ABUSECH_AUTH_KEY` | ThreatFox, MalwareBazaar, URLhaus | free — https://auth.abuse.ch |
| `OTX_API_KEY` | AlienVault OTX (optional) | otx.alienvault.com → Settings |
| `ABUSEIPDB_API_KEY` | AbuseIPDB blacklist (optional) | abuseipdb.com → API |
| `DISCORD_BOT_TOKEN` | posting cards | step 2 |
| `DISCORD_CHANNEL_ID` | which channel | step 2 |
| `DISCORD_ALLOWED_USER_IDS` | defence-in-depth check in apply | your Discord user id |

Sources without their key are skipped (shown in the run summary), everything else still runs.

### 2. Discord app
1. https://discord.com/developers/applications → **New Application** (`IOC Watcher`).
2. **Bot** → Reset Token → copy → GitHub secret `DISCORD_BOT_TOKEN`.
3. **OAuth2 → URL Generator** → scope `bot`, permissions *Send Messages, Embed Links, Read Message History* → open the URL, add to your server.
4. Create `#ioc-review`; Discord settings → Advanced → Developer Mode on; right-click channel → Copy ID → `DISCORD_CHANNEL_ID`. Right-click yourself → Copy User ID → `DISCORD_ALLOWED_USER_IDS`.

### 3. Cloudflare Worker (button handler)
```powershell
cd worker
npx wrangler login
npx wrangler secret put DISCORD_PUBLIC_KEY        # app → General Information → Public Key
npx wrangler secret put DISCORD_APPLICATION_ID    # app → General Information → Application ID
npx wrangler secret put ALLOWED_USER_IDS          # your Discord user id
npx wrangler secret put GITHUB_TOKEN              # fine-grained PAT: only ioc-watcher, Contents read/write
npx wrangler deploy                               # prints https://ioc-watcher-discord.<you>.workers.dev
```
Then Discord app → **General Information → Interactions Endpoint URL** = that workers.dev URL → Save (Discord sends a signed PING; it only saves if verification passes).

### 4. Laptop vault sync
```powershell
git clone https://github.com/RyanPendergast12/ioc-watcher C:\Users\Ryanp\ioc-watcher   # already done
pip install -r requirements.txt
python tools\build_mapping.py           # re-run whenever you add/rename a vault page, then commit mapping.yml
powershell -ExecutionPolicy Bypass -File sync\install_task.ps1
```
Log: `%LOCALAPPDATA%\ioc-watcher\sync.log`. Manual run / preview: `python sync\vault_sync.py --dry-run`.

### 5. First run
Actions → **ioc-watcher-detect** → Run workflow. The first run is a bootstrap: it only looks back 3 days (7 for KEV) and baselines Spamhaus DROP, so you get a manageable first batch. After that it runs daily at 11:17 UTC.

## Using it
* **Approve**: proposal → `approved/`; within ~15 min the laptop task appends it to the page.
* **Deny**: proposal → `archive/denied/`; IOCs stay in the seen-list so they are not re-proposed.
* **Edit**: opens a form with *Remove* / *Add* boxes (one IOC per line, defanged OK) → approves the edited set.

## Local testing
```powershell
python -m watcher.detect --dry-run                 # writes ./dry-run/*.json, touches nothing else
python -m watcher.detect --dry-run --only threatfox,"The DFIR Report"
python sync\vault_sync.py --dry-run --no-pull
```

## Notes
* Only vault **file names** are published here (via `mapping.yml`). Page content never leaves the laptop. Because this repo is public, proposals and approved IOCs are visible to anyone. They all come from public OSINT, but switch the repo to private if that matters to you.
* Blogs that refuse automated clients (Sophos, Trellix) are disabled rather than worked around.
